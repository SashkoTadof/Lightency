# Project guidance

## Code comments

When adding or changing comments, use a short English tag that describes the change:

- `// +added function: ...` for a new function or capability.
- `// ~improved optimization: ...` for a performance improvement.
- `// !fixed bug: ...` for a bug fix.
- `// =changed behavior: ...` for an intentional behavior change.

Keep comments brief and explain intent or a non-obvious constraint; do not restate what the code already says. Add them only where they help explain a change.
